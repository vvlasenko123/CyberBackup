# Просмотр защищённых файлов в браузере

Ветка: `backend/BCD-84`.

К существующим маршрутам выдачи файлов добавлен необязательный query-параметр `inline: bool`, по умолчанию `false`. Для просмотра передайте `?inline=true`. Тело запроса не требуется.

| Метод и путь | Доступ |
| --- | --- |
| `GET /public/api/v1/laboratories/{laboratoryId}/reports/my/versions/{versionId}/file?inline=true` | Пользователь из JWT должен быть владельцем отчёта; версия должна принадлежать отчёту указанной работы |
| `GET /public/api/v1/teacher/reports/{reportId}/versions/{versionId}/file?inline=true` | Преподаватель группы студента — владельца отчёта, либо `admin` / `superadmin`; версия должна принадлежать указанному отчёту |
| `GET /public/api/v1/questions/{questionId}/attachments/{attachmentId}?inline=true` | Только `student`, автор вопроса; вложение должно находиться в этом вопросе |
| `GET /public/api/v1/teacher/questions/{questionId}/attachments/{attachmentId}?inline=true` | Преподаватель группы автора вопроса, либо `admin` / `superadmin`; вложение должно находиться в этом вопросе |

Все ID в путях — GUID. На маршруте собственных отчётов, как и раньше, разрешены все четыре роли, но проверяется владение отчётом по ID пользователя. Авторство лабораторной работы для преподавательского чтения файла отчёта не требуется. Закрытый вопрос остаётся доступен для чтения вложений.

Аутентификация: cookie `access_token` или `Authorization: Bearer <JWT>`. Проверка роли и доступа к ресурсу выполняется до чтения файла из MinIO. Ссылки на публичный объект хранилища не выдаются.

## Ответ

При `inline=true` форматы `application/pdf`, `image/jpeg`, `image/png`, `image/gif` возвращаются с `Content-Disposition: inline`. Имя файла передаётся в `filename` и `filename*` с поддержкой Unicode. Тело ответа — исходные байты файла, `Content-Type` — сохранённый MIME-тип.

Остальные типы, включая DOCX, возвращаются как скачивание (`Content-Disposition: attachment`) даже при `inline=true`. Конвертация DOCX в HTML/PDF не выполняется; существующий клиент может продолжать отображать DOCX через свой компонент предпросмотра. При отсутствии параметра или `inline=false` сохраняется скачивание всех форматов.

Все успешные ответы с файлом, включая скачивание, содержат:

```http
Cache-Control: private, no-store
X-Content-Type-Options: nosniff
```

Для поддерживаемых форматов в режиме просмотра включена обработка `Range`. После проверки доступа ASP.NET нормализует диапазон по размеру файла, сохранённому в БД; затем смещение и длина передаются в MinIO через `WithOffsetAndLength`. SDK копирует ответ непосредственно в HTTP-поток с буфером 64 КиБ, без загрузки всего объекта в память. Например, запрос 64 КиБ из PDF размером 10 МиБ читает из MinIO только 64 КиБ. Проверка доступа выполняется и для запросов диапазона. При `416` чтение объекта не выполняется.

| HTTP | Значение / формат |
| --- | --- |
| `200` | Файл целиком |
| `206` | Запрошенный диапазон байтов; заголовок `Content-Range` |
| `400` | Невалидное значение `inline`, например `inline=invalid`; стандартный `ValidationProblemDetails` |
| `401` | Нет действительного JWT; файл не читается |
| `403` | Роль не разрешена для маршрута; файл не читается |
| `404` | Ресурс/файл не найден, связан с другим родительским ресурсом либо недоступен пользователю; JSON `{ "message": "..." }`, без содержимого файла |
| `416` | Диапазон за пределами файла; `Content-Range: bytes */<размер>` |
| `500` | Ошибка инфраструктуры; JSON `{ "message": "Внутренняя ошибка сервера" }` |

Для отсутствующей или недоступной версии отчёта исправлено сопоставление `laboratory_report_version.not_found`: теперь `404` вместо прежнего `500`. Остальные бизнес-ошибки лабораторных не изменены. Ошибки получения объекта из хранилища обрабатываются как инфраструктурные ошибки.

## Проверка

```powershell
dotnet test backend/Apps/CyberBackup/Tests/Api.Tests/Api.Tests.csproj -c Release
```

HTTP-тесты используют реальные контроллеры, JWT, сервисы и обработчик ошибок. Проверяются просмотр/скачивание, MIME-типы, Unicode-имена, приватные заголовки, диапазоны, роли, чужие ресурсы, несовпадающие ID и отсутствие обращений к хранилищу при отказе в доступе. Регрессионные тесты диапазонов используют настоящий MinIO SDK с тестовым HTTP-транспортом: проверяют отправленный в S3 заголовок `Range` и число прочитанных байтов на объекте 10 МиБ. БД заменена тестовой зависимостью; SQL-проверки членства в группах и доступность реального MinIO требуют проверки с подключёнными сервисами.
